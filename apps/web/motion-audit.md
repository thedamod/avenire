# Motion audit: Avenire v2 web (Emil Kowalski bar)

Scope: `packages/ui` and `apps/web`. **Excluded** (follow-up pass): `apps/web/src/features/sources/**`,
`apps/web/src/app/(auth)/**`, `apps/web/src/features/auth/**`. Everything below is built so that
pass only has to apply existing tokens, utilities and components.

Written 2026-10-21 against `feat/frontend-v2` (with the uncommitted work in the tree).

## 1. Recon

**Stack.** Next 16.3 app router, React 19.3, Tailwind v4, Radix (`radix-ui` 1.6) primitives
wrapped in `packages/ui`, `tw-animate-css` 1.4 for Radix enter/exit keyframes, sonner 2.0.8,
LegendList for the chat thread. No motion library. Motion lives in CSS: tw-animate
`animate-in/out` + `data-[state]` classes, Tailwind `transition-*`, three hand-written keyframes
(`avenire-sweep`, `ruth-shimmer`, sonner's own).

**Tokens that already existed** (`packages/ui/src/styles/globals.css`): `--ease-out`,
`--ease-in-out`, `--ease-drawer` (Emil's values) and `--duration-fast/normal/moderate/slow`
(100/160/200/300ms). Nothing used them: every component used Tailwind's default
`cubic-bezier(0.4,0,0.2,1)` 150ms or tw-animate's default `ease` 150ms. The `--duration-*`
values had no utilities (Tailwind v4 has no `duration` theme namespace), so they were dead.

**Personality.** Crisp, dark, quiet study tool. Motion should be fast and nearly invisible;
the only delight budget is the morning toast (seen once a day) and Ava's ephemeral answer.

### Scroll fades (new)

The app had no edge fades; long scroll areas cut content hard against headers and the composer.

- **One utility, one hook.** `edge-fade-y` / `edge-fade-x` (CSS `mask-image: linear-gradient`)
  driven by `data-scroll-fade="start end"` on the scroller. `attachScrollFade(el)` /
  `useScrollFade()` / `<ScrollFade>` in `packages/ui` set that attribute from a passive scroll
  listener throttled to one `requestAnimationFrame`, plus a `ResizeObserver` on the scroller and its
  children. The attribute only changes when an edge state flips (a couple of times per gesture), so
  there is no per-frame React state and no per-frame style recalculation.
- **Why not `animation-timeline: scroll()`.** It needs to animate custom properties for the mask
  stops, which are never compositor-accelerated: Chrome would recalculate style on the scroller
  every scroll frame. The attribute approach does work only on edge changes and runs everywhere
  (Firefox has no scroll timelines).
- Fade sizes animate through `@property --edge-fade-start/--edge-fade-end` registered with
  `inherits: false`, so changing them never restyles the (huge) subtree.
- The mask goes on the **scroller**, never on a surface with a border or shadow (a mask clips
  `box-shadow`). Menus get an inner scroll viewport for this reason.
- `--edge-fade-inset-end` lets the chat fade end _at the composer's top edge_ (the dock floats
  over the list).

Applied to: chat thread (top under the header, bottom into the composer), report thread, report
output pane body and tab row (x), phone "Made overnight" row (x), ephemeral answer, composer tray
overlay + tray lists, sheet bodies (`ResponsiveDialog`, schedule sheet, citation sheet, notebook
picker), dropdown/context menus and select viewports, `AddContext`, task source select, home
Sources filter chips (x), home notebook shelf phone strip (x), notebook sources strip (x), tasks
phone filter chips (x), mention menu.

Not applied, on purpose: home lists, tasks list, trash list and settings scroll **with the
document**, not inside a scroller. Turning them into inner scrollers would break iOS toolbar
collapse, pull-to-refresh and scroll restoration; the glass phone headers already blur what
passes under them. The settings nav is sticky and never scrolls.

## 3. Rejected candidates

- **Mention menu (`@`) and slash menu open animation.** Keyboard-initiated, typed many times a
  day. Stays instant.
- **Thinking/tool-activity expand inside the chat thread.** The row lives in a virtualised
  LegendList; animating its height fights item measurement and scroll anchoring. Stays instant.
- **Animating streamed tokens / a typewriter fade per word.** Constant, functional reading content.
- **Stagger on home lists.** Home is visited tens of times a day; stagger would replay every visit.
- **View Transitions for route changes.** See finding 20.
- **Hold-to-delete on "Delete forever" in Trash.** It already has a confirm dialog; adding a second
  deliberate gesture slows a rare destructive action without preventing more slips.

## 5. Follow-up for the auth + viewer pass

Use, don't re-invent: `duration-*`/`ease-*` tokens, `page-enter`, `enter-fade`,
`edge-fade-y/x` + `useScrollFade`/`ScrollFade`, `usePresenceList`, `motion-press` (press
scale), and the `packages/ui` overlays. Viewer specifics to look at: page thumbnails strip
(x fade), find bar (keyboard-opened: no animation), `ViewerDock` (dock pattern), PDF page
skeleton → canvas (`enter-fade`), transcript list (y fade). Auth: form step swaps (crossfade +
`blur(2px)`), error line (`enter-fade`), submit button press.
